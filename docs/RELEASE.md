# Codex Switcher 0.1.4 Demo

支持将官方账号或直连 API 单独应用到 Remote-SSH 服务器，同步同一账号的文件登录，修复 Windows 更新检查并识别需要更新的旧远端代理。Windows、Mac Apple Silicon 和 Intel 从同一提交构建。

## 本版更新

- **远程服务器分页**：提供接入说明，连接 VS Code Remote-SSH 后，可选择已保存的官方账号或可直连的自定义 API，确认后单独应用；本机与服务器可以使用不同来源，互不跟随。
- **官方登录互通**：同一账号以 `last_refresh` 最新的文件登录为准，同步到已使用该账号的本机和在线服务器。登录同步不改配置、不重载窗口；不同账号保持独立。
- **远端代理**：新增 `codex-switcher-remote.vsix`，在 SSH 窗口中安装到服务器侧；本机伴随扩展固定运行在 UI 宿主。按服务器与 Codex 配置目录分组，同目录只写一次，并请求相关窗口重载。
- **配置与登录写入**：写前核对读取时的 SHA-256，首次分别保留 `config.toml.switcher-backup` 和 `auth.json.switcher-backup`，以临时文件加改名写入，权限为 `0600`。远端正文、登录令牌和密钥不写入本机客户端记录、切换任务或日志。
- **远端代理识别与诊断**：通过协议号 2 识别同为 `0.1.4` 的旧代理并提示更新；诊断导出包含代理版本、协议号、系统、配置目录、模型与脱敏账号摘要。写入成功与重载完成分别判断。
- **账号显示**：套餐从最新保存的登录声明读取；显示可用的订阅到期、读取及登录刷新时间，支持独立刷新与全部刷新。修复手机端长账号说明撑宽页面的问题。
- **更新检查**：通过本仓库最新 Release 检查更新，以只增不减的发行序号判断，安装前核对 SHA-256、包内构建号和序号；开发目录通过 Git 更新。
- **Windows 更新修复**：修正系统无法在线完成证书吊销检查时的更新失败，保留 TLS、主机名和包校验，错误提示使用中文。
- **本机登录提示**：使用 API 时，账号管理会将本机 `auth.json` 中保留的账号标为“本机登录”，并说明为何暂时不能移除。

## 下载与安装

| 平台或扩展        | 文件                             | 用法                                                            |
| ----------------- | -------------------------------- | --------------------------------------------------------------- |
| Windows x64       | `codex-switcher-windows-x64.zip` | 完整解压后打开 `Codex Switcher/Start.cmd`，或运行 `install.cmd` |
| Mac Apple Silicon | `codex-switcher-macos-arm64.zip` | 运行 `Install.command`，或打开 `Codex Switcher.app`             |
| Mac Intel         | `codex-switcher-macos-x64.zip`   | 同上                                                            |
| 本机伴随扩展      | `codex-switcher-companion.vsix`  | 在本机编辑器安装，已有窗口首次需要重载                          |
| 远端代理          | `codex-switcher-remote.vsix`     | 通过“远程服务器”页安装，或在 Remote-SSH 服务器侧手动安装        |

应用、伴随扩展与远端代理版本均为 `0.1.4`，请配套更新。每个文件附 SHA-256 校验文件。桌面包内置 Node.js 和依赖，不含个人账号、密钥或聊天数据。

请先安装 Codex 桌面版或 OpenAI 官方 Codex 编辑器扩展。使用启动器打开的地址建立本机会话；后台重启后请重新运行启动入口。仅输入本机地址不会取得新的会话。

## 从旧版本升级

**已安装的 0.1.3 仍检查固定的旧版地址，不能自动发现 0.1.4，请手动下载并安装一次。** 0.1.4 起检查本仓库的最新 Release，后续可使用页面的检查更新。

更新时保留原有账号数据目录，自定义 `BRIDGE_HOME` / `CODEX_HOME` 继续沿用原路径。Windows 解压版请保留 `private/`，安装版可运行新包的安装器；Mac 运行新包 `Install.command`。同时更新本机伴随扩展并重载已有窗口；远端代理版本必须与伴随扩展一致。

**已安装早先 0.1.4 的用户可正常一键升级到本次替换构建**，无需因版本号相同而手动下载。只有检查更新失败（例如 Windows 提示证书吊销检查无法完成）的电脑需要手动下载安装一次，修复已包含在本版中。

升级后请在“编辑器与诊断”点击“一键更新扩展”，再到“远程服务器”页按提示更新远端代理。两份扩展的版本号仍为 `0.1.4`，新远端代理使用协议号 2。

内置更新只接受更大的发行序号，下载地址固定为本仓库，保留 TLS 和 SHA-256 校验。新后台未通过启动检查会恢复旧版。开发目录、只读安装位置及 Mac AppTranslocation 请手动更新。

## 远程功能边界与验证

远程功能为 Demo，尚待真实 Remote-SSH Linux 使用环境验收。自动化覆盖配置读写、校验与备份、权限、内存通道、接口、界面和 VSIX 安装，不能替代服务器上的真实 API 请求、聊天恢复及网络验证。

仅支持 Remote-SSH、文件存储的官方登录及已确认可直连且有密钥的自定义 API。服务器显式使用 `keyring` 或 `ephemeral` 时拒绝官方账号应用，不改变其存储方式。不同步经本机转换的 API 或服务器旧对话；官方与 API 之间切换后，另一来源创建的旧对话可能不显示。服务器网络由使用者配置，WSL、Dev Container 暂不支持。伴随扩展连接本机服务，SSH 到一台本身运行切换器的机器的方式不受支持。

登录互通按在线状态定期同步，不能代替跨机器的刷新锁；同一账号跨机器续期与服务器上的实际对话仍需在具体环境验证。

密钥通过 VS Code 自己的 SSH 通道写入服务器。同一窗口里的其他扩展也能调用远端代理命令，遵循 VS Code 的扩展信任边界。切换及重载可能中断运行中的任务，请先保存工作；“已写入，已请求重载”不代表真实模型请求已经成功。

## 平台验证与已知限制

发布前运行 Windows、macOS Apple Silicon 与 Intel 的回归、浏览器入口、额度界面、安装包解压启动及真实 VS Code 多窗口检查，六项任务通过后才上传资产。macOS 另检查系统 Bash 安装、重复安装、数据保留、签名完整性与 LaunchServices 启动。

Mac 应用使用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证；首次打开可能需要在“系统设置 → 隐私与安全性”允许。编译目标为 macOS 12+，CI 在 macOS 15 验证；其他系统版本和实际账号登录、额度及编辑器关联仍受本机环境影响。

若本机或远程操作失败，可在“编辑器与诊断”导出脱敏日志供排查。日志仅保存在本机，不自动上传。VS Code 已覆盖多窗口检查；Insiders、Cursor、Windsurf 仍需在相应编辑器版本上人工验证。
