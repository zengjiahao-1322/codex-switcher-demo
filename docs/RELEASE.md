# Codex Switcher 0.1.3 Demo（界面整理与一键升级）

2026-10-23 发布 0.1.3，整理来源卡片与管理页签，提供检查更新、校验下载和失败回滚。Windows、Mac M 系列和 Mac Intel 从同一提交构建。

## 本版更新

- **界面整理**：当前来源、额度、编辑器状态和最近切换结果集中显示，来源卡片直接切换；账号、API、编辑器与诊断、设置分别管理。页面改用原生 JavaScript 模块和独立样式，无需前端框架或打包工具。
- **一键升级**：设置里检查本仓库的发布信息，含发行序号的构建只接受更大序号的更新。用户点击后下载对应平台包，核对 SHA-256、发行序号和构建号，使用新包的独立进程替换程序；保留最近一份备份，新后台 30 秒内未通过构建号健康检查则恢复旧版。账号数据目录不参与替换；开发目录、Mac 只读位置或 AppTranslocation 需手动更新。升级后自动打开带新会话的页面。
- **更新编辑器扩展**：按检测到的编辑器安装本版伴随扩展，并在用户确认后重载已接入窗口，逐项显示结果；这些重载会中断窗口中的任务。
- **诊断日志导出**：在“编辑器与诊断”下载脱敏诊断文件，包含当前环境、切换步骤耗时、进程链、配置目录、窗口关联结果和官方账号错误。日志仅保存在本机，最多三份、每份约 2 MiB；导出最近 2000 条，不包含对话正文，也不会自动上传。
- **启动和心跳开销**：缓存稳定的窗口关联，多个窗口共享短期进程扫描结果，合并无变化的登记写入；Mac 定期进程扫描改为异步，首屏请求并行加载。成功收紧权限后复用同一路径的结果，数据目录迁移后重新处理。隔离 Windows 实测第二次启动约 542 → 127 ms，三窗口 30 秒扫描约 12 → 5 次、写入 44 → 15 次；这是同一测试环境的对比，不代表所有机器耗时。
- **伴随扩展长轮询**：协议 3 最长等待 10 秒，发现重载命令立即回复；等待结束后重新确认连接状态，断开时清理定时器。隔离实测空闲请求由每窗口每分钟 30 次降至约 6 次，五轮命令到确认约 4–340 ms。需重新安装本次 VSIX 并重载已有窗口。
- **后端关联**：按真实后端的进程归属和配置目录关联编辑器，远程工作区或 WSL 设置不再否决已确认的本机后端。远端 extension host 的心跳会保留，并在同一远端 `CODEX_HOME` 且窗口唯一时关联后端。网页和伴随扩展统一显示“已接入”“后端未关联”或“独立配置”；旧版扩展仍显示“已连接”时会明确提示更新 VSIX。
- **重载确认**：新窗口的伴随扩展连通后，继续等待对应 Codex 后端出现并确认共用配置，再报告重载完成。撤回没有得到真实进程验证支持的重复停止逻辑。
- **进程与同步开销**：Windows 改用随包构建的 C# 进程助手，桌面与插件释放并行；较大的旧对话批次由两个官方后端动态分担，总在途数仍限制为四条，保留完整冷启动核对。Windows 安装器同步更新助手，不沿用旧源码构建出的程序。
- **本机访问和配置**：页面不再自动下发访问会话，启动器通过当前凭证建立会话；失效时提示从快捷方式重新打开。自定义 Codex 程序路径需用户确认，心跳只接受可信安装路径。Windows 启动时收紧数据目录权限，失败时显示具体提示。
- **切换速度**：账号/API 验证与编辑器归属检查并行，全部通过后才应用；Windows 使用退出信号确认进程关闭，后台启动移除固定 1.5 秒等待。旧对话速度设置从文件末尾读取，同步和核对最多四条并发；不减少登录、退出或持久化校验。实际总耗时仍取决于账号网络服务、历史规模与桌面退出速度，不承诺所有切换都在 10 秒内。
- **登录与额度**：修复登录回调提前到达、旧通知覆盖结果和重试共用目录的问题；访问令牌到期先向官方刷新确认，不把网络错误等同登录失效。额度最多同时读取两个账号，按账号显示结果，失败时隐藏旧数字。
- **同实例多窗口**：优先按扩展宿主进程关联 VS Code 窗口；切官方账号即使模型未变，也释放旧插件后端并请求重载。Windows 与 Mac 使用同一套隔离窗口验收场景。
- **桌面自动重启**：修复空闲桌面与插件并存时漏检桌面的问题，重开后确认同目录的新主进程；桌面壳和后端不再重复显示，按实际后端目录确定范围。Windows 排除同名渲染子进程，Mac 排除普通 ChatGPT.app。
- **插件重载与恢复**：自动重载前检查伴随扩展连接，直接展示接入状态；旧对话同步失败后恢复已经停止的插件，保留失败结果，避免留下无响应面板。独立配置窗口不跟随。
- **切换反馈**：展示各步骤、耗时和每个窗口的等待、接收、重载完成或失败；“扩展已重载”不等于实际模型请求已经验证。
- **低额度提醒**：当前官方账号近期成功读取、尚未重置的订阅窗口剩余额度不超过 20% 时提醒；备用账号按钮只选中账号，不自动应用或重启。
- **旧对话跟随切换**：网页切换默认全部跟随，不再弹出选择。保留目标支持的原模型、消息、工具记录、项目目录和各对话原有速度；MCP/CLI 仍可显式选择关闭、只跟随切换前的供应商或全部跟随。部分失败显示计数并允许继续同步，完成后核对保存结果。
- **网页入口**：从启动器打开后，同一会话可新开标签页或刷新；没有有效会话时显示重新打开入口的提示。读取失败时显示错误，避免一直停在加载中。
- **界面精简**：删除独立 Fast 检测、提示和默认速度展示，仅保留普通 API 检测；不新增标准／Fast 模型别名。已有 Codex 速度设置和协议转换中的服务档位传递保留。

## 下载与启动

| 系统        | 下载文件                         | 启动方式                                                                |
| ----------- | -------------------------------- | ----------------------------------------------------------------------- |
| Windows x64 | `codex-switcher-windows-x64.zip` | 完整解压，双击 `Codex Switcher/Start.cmd`；需要安装时运行 `install.cmd` |
| Mac M 系列  | `codex-switcher-macos-arm64.zip` | 解压，运行 `Install.command`，或打开其中的 `Codex Switcher.app`         |
| Mac Intel   | `codex-switcher-macos-x64.zip`   | 启动方式同上                                                            |

请先安装 Codex 桌面版或 OpenAI 官方 Codex 编辑器扩展。每个包内置对应系统的 Node.js 和依赖，无需另装 Node、npm 或 Python；包内不含个人账号、密钥、聊天或验证数据。随包提供 SHA-256 校验文件。

伴随扩展单独提供 `codex-switcher-companion.vsix`，Windows / Mac 通用。在编辑器里选择“从 VSIX 安装”，或通过切换器重新接入。**即使已安装过 0.1.3，也需要重新安装本次 VSIX（`reloadProtocol: 3`）**；已有窗口首次需要执行一次“重载窗口”激活新代码。打开 Codex 后，确认各窗口状态栏显示“Codex Switcher · 已接入”；仍显示“已连接”说明旧扩展还在运行。“后端未关联”只表示连到了服务，还没有确认对应的 Codex 后端。

请从 `Start.cmd`、桌面快捷方式或 Mac 应用打开页面，使用启动器给出的地址建立会话。仅输入 `http://127.0.0.1:47831/` 不会取得新的访问凭证；后台重启后请重新运行启动入口。首次使用需要添加自己的账号或 API 配置。

## 更新现有安装

安装本版后，可在“设置”检查更新或使用顶部更新提示；下载地址固定为本仓库，不接受自定义更新地址。升级保留账号数据，新后台会打开新的页面，旧页面提示关闭。伴随扩展可在页面中一键更新，重载前请保存任务。

包含发行序号的新构建只接受序号更大的更新，相同或更旧的发布不会触发安装。安装前同时核对包内序号、构建号及 SHA-256。早期 0.1.3 仍按构建号提示更新，可以升级到含发行序号的构建；升级后使用新规则。开发目录只显示发布信息，请通过 Git 更新。

旧版尚无一键升级入口，需先退出旧版切换器，使用新包启动或安装。保留已有数据目录；使用自定义 `BRIDGE_HOME` / `CODEX_HOME` 的用户应继续沿用原目录。仅替换切换器程序不需要切换账号或重启 Codex；点击“切换到这里”切换来源时，目标客户端才会重启或重载。

## 验证范围与已知限制

源码中的远程服务器功能尚未发布，当前下载不包含该功能。它采用独立分页单独应用 API，不跟随本机切换；仅支持 Remote-SSH 和已确认直连且有密钥的自定义 API。发布前仍需真实服务器确认新 API 生效、聊天可打开、文件权限为 0600，以及本机切换不影响远端。

发布流水线在 Windows、macOS 15 Apple Silicon 和 Intel 运行回归、真实浏览器入口与额度刷新检查、安装包解压启动，以及真实 VS Code 多窗口重载检查；六项任务通过后才会发布。测试使用隔离配置和合成数据，不上传个人凭据。

macOS 另验证系统 Bash 安装脚本、首次与重复安装、数据保留、签名完整性和 LaunchServices 启动。应用使用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证；浏览器下载后的首次打开仍可能需要在“系统设置 → 隐私与安全性”中手动允许。不同系统版本和本地安装方式可能需要额外确认。

**运行边界**：关联取决于实际 Codex 后端的进程和配置目录，不能仅凭窗口标签判断。自动化检查使用隔离配置和测试数据；实际编辑器关联、账号登录和额度显示取决于本机环境。

如果编辑器没有完成关联或重载，请先安装与切换器版本一致的伴随扩展，并导出诊断日志后再排查；自动化检查结果不能替代每台设备的本地验证。

已确认共用本机配置的编辑器窗口会一起重载，独立目录及真正运行在 WSL、SSH 和容器中的远端后端不自动跟随；窗口标签不否定真实的本机后端关联。重启或重载可能中断正在运行的任务，请等任务完成并保存工作后再切换；已保存的聊天文件会保留，运行中的任务和未保存状态不能保证自动恢复。Cursor、Windsurf、Insiders 尚未逐款完成与 VS Code 相同的 GUI 验收。

本次替换 `v0.1.3`，应用与伴随扩展版本均为 `0.1.3`。请重新下载桌面包并在每个编辑器窗口重新安装 VSIX。
